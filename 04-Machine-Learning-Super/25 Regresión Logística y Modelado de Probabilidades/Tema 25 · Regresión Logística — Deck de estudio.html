01 · EL PROBLEMA

Una recta no sabe
dónde detenerse

Una regresión lineal predice valores entre $-\infty$ y $+\infty$. Pero una probabilidad nunca puede ser menor a 0 ni mayor a 1 — necesitamos una función que comprima cualquier número real dentro de ese rango.

01 · LA SOLUCIÓN

La función Sigmoide

S(z) = 1 / (1 + e^-z)
  • Actúa como un embudo: cualquier z real cae siempre en (0, 1).
  • S(0) = 0.5 → el umbral estándar corresponde exactamente a z = 0.
  • Simetría: S(−z) = 1 − S(z).
01 · INTERPRETACIÓN

De la probabilidad al log-odds

Si despejamos z de la sigmoide obtenemos el logit: el modelo es lineal en el log-odds, no en la probabilidad.

# logit: el modelo SÍ es lineal aquí ln( p / (1-p) ) = β₀ + β₁X₁ + β₂X₂ + ... + βₙXₙ

Odds = p / (1−p)
p=0.8 → odds = 4 (4 a 1 a favor)

β > 0
e^β > 1 → sube la probabilidad de clase positiva

β < 0
e^β < 1 → baja la probabilidad de clase positiva

01 · ENTRENAMIENTO

Máxima Verosimilitud,
no mínimos cuadrados

Se buscan los β que maximizan la probabilidad de haber observado las etiquetas reales. No tiene solución cerrada: se resuelve con optimización numérica (descenso de gradiente, Newton-Raphson…) — de ahí nacen los solvers de la sección 5.

ℓ(β) = Σ [ yᵢ ln(pᵢ) + (1-yᵢ) ln(1-pᵢ) ]
Matiz clave: scikit-learn no maximiza la verosimilitud pura — añade regularización L2 (parámetro C). Por eso la escala de las variables sí importa.
02 · DIAGNÓSTICO

La matriz de confusión

Predicho: PositivoPredicho: Negativo
Real: PositivoVPFN
Real: NegativoFPVN
  • TPR / Sensibilidad = VP / (VP + FN) → % de positivos reales atrapados.
  • FPR = FP / (FP + VN) → % de falsas alarmas sobre negativos reales.
  • Cada punto de la curva ROC es un umbral distinto.
02 · MÉTRICA RESUMEN

Curva ROC y AUC

  • AUC = 1.0 → separación perfecta entre clases.
  • AUC = 0.5 → equivale a lanzar una moneda (la diagonal).
  • Interpretación probabilística: P(score del positivo > score del negativo), elegidos al azar.
  • Mide qué tan bien ordena el modelo — no si la probabilidad está bien calibrada.

04 · PREPROCESAMIENTO

La trampa del else silencioso

❌ frágil
def transformar(nombre): if nombre in ['drugA','drugB','drugC']: return 1 else: return 0 # ¡cualquier cosa cae aquí!
✓ explícito
MAPA = {'druga':1, 'drugb':1, 'drugc':1, 'drugx':0, 'drugy':0} y = nombre.str.lower().map(MAPA) assert y.isna().sum() == 0

El CSV real mezcla mayúsculas (DrugY vs drugX). Un mapeo con else oculta cualquier fármaco mal escrito clasificándolo como Extranjero, sin avisar.

06 · CODIFICACIÓN CATEGÓRICA

El experimento que cambia todo

Comparamos 3 formas de codificar BP con validación cruzada de 5 pliegues:

CodificaciónLógicaAccuracy (CV)AUC (CV)
A) Alfabético (=LabelEncoder)HIGH=0, LOW=1, NORMAL=20.9550.988
B) Orden clínicoLOW=0, NORMAL=1, HIGH=20.8000.860

¿Por qué gana A "por casualidad"? La relación de BP con el objetivo no es monótona: NORMAL nunca es Nacional, pero HIGH y LOW sí pueden serlo. Un modelo lineal solo puede representar un efecto monótono con un único coeficiente — el orden alfabético deja a NORMAL en un extremo por azar. One-Hot es la opción segura para categorías sin orden real.

05 · SOLUCIONADORES

Cuatro caminos, el mismo destino

SolverFamiliaPenalizacionesCuándo destaca
lbfgsCuasi-NewtonL2, ningunaEstándar por defecto
newton-cgNewton (2º orden)L2, ningunaAlta precisión, pocas variables
sagGradiente estocásticoL2, ningunaDatasets masivos (escalado obligatorio)
sagaGradiente estocásticoL1, L2, ElasticNetGrandes + selección de variables

Con los 4 solvers: accuracy = 0.950, AUC = 0.991 — idénticos. La log-loss es convexa: tiene un único mínimo global, así que un solver que converge bien siempre llega al mismo modelo. Lo que cambia es cómo llega: velocidad, memoria, penalizaciones soportadas.

05 · DECISIÓN

El umbral 0.5 es solo una convención

UmbralPrecisionRecallFN
0.20.6111.0000
0.50.9090.9091

  • Bajar el umbral → más recall, más falsos positivos.
  • Subir el umbral → más precision, se escapan positivos reales.
  • La elección depende del costo real de cada error — en medicina o finanzas, no es simétrico.
  • Índice de Youden: umbral que maximiza (TPR − FPR).

07 · PARA NO OLVIDAR

Errores comunes

  • 1LabelEncoder en predictoras → impone un orden numérico arbitrario. Usa OneHotEncoder salvo que el orden sea real y monótono.
  • 2Ajustar el scaler con todos los datos → fuga de datos. Ajusta solo con train, o mejor, dentro de un Pipeline.
  • 3Confiar solo en accuracy con clases desbalanceadas → compara siempre contra la línea base.
  • 4Aceptar el umbral 0.5 sin pensar → depende del costo real de cada tipo de error.
  • 5Ignorar un ConvergenceWarning → el solver no llegó al óptimo: escala las variables o sube max_iter.
